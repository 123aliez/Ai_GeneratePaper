# Paper Agent — 实验数据驱动的多 Agent 论文初稿生成框架

放入材料 → 一条命令 → 得到一篇论文初稿(Markdown + LaTeX 工程)。

你提供**创新点**(idea)、**实验结果表**、**参考文献笔记**和**实验代码**,三个异构大模型
Agent 逐章完成"备料 → 挖证据 → 规划 → 分段起草 → 评审 → 收敛修订 → 定稿 → 跨章交接",
最后由程序把各章组装成整篇。全程被确定性的 Python 代码编排和把关。

> 这份文档讲**它是什么、怎么用、每份材料怎么写**。
> 每步干什么见 `工作流总览.md`;每份产物是什么见 `文档说明.md`;代码文件各干什么见 `代码结构.md`;
> 常见问题见 `启动说明.md`。

---

## 它解决什么问题

让 LLM 直接"写一篇实验论文",最大的坑是**幻觉**:把没跑过的实验编成漂亮数字,把别人的
论文说得似是而非,把结论说得比证据强。这个框架的核心目标不是"写得流畅",而是
**保证贡献、数字、引用都来自你提供的材料,绝不替你编**:

| 维度 | 唯一来源 | 缺了会怎样 |
|---|---|---|
| **贡献是什么** | `inbox/idea.md`(你写的创新点、核心洞察、方法设计) | 材料检查直接报错 |
| **数字是什么** | `inbox/results/*.csv`(你的最终结果表) | 结果类章节拒绝起草;其余章节不许写结果数字 |
| **引用什么** | `inbox/references/refs.bib` + 你的文献笔记 | 不在 bib 里的 key 一律不是合法引用 |
| **结构是什么** | `inbox/outline_draft.md`(你手填的章节骨架表) | 材料检查直接报错 |

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env                       # 填三组 provider / model / key(OpenAI 或 Claude 各自独立)

python run.py --new 我的论文                # 在 projects/ 下建项目,放好所有模板
# 把材料放进 projects/我的论文/inbox/ (下面逐项说明)

python run.py --project projects/我的论文 --check   # 先看材料有没有问题(不调模型)
python run.py --project projects/我的论文 --go      # 建索引 → 展开大纲 → 停下等你审
# 审 projects/我的论文/outline.zh.md:改小节、要点,补 (~N words)
python run.py --project projects/我的论文 --go      # 逐章生成 → 组装到 output/
```

出错、中断、手改了某章终稿——**重跑同一条 `--go` 即可**:已完成的章自动跳过;手改过的终稿
只重新核验和组装,不重写。改了 idea.md / 结果表 / 实验设置 / 文献库等输入后,已完成的章会按陈旧
硬停并列出陈旧产物(备份后删掉再跑),不会静默复用。

## 项目文件夹

```
projects/我的论文/
├── inbox/                     你的全部材料(系统只读)
│   ├── idea.md                创新点文档(最重要)
│   ├── outline_draft.md       章节骨架表(你手填:几章、每章叫什么、什么 type)
│   ├── results/               每个 CSV 是论文里的一张结果表 + 实验设置.md
│   ├── references/            refs.bib + 每篇文献一个文件夹(笔记 md + 原文 md)
│   ├── code/                  实验代码(只做静态索引,不执行)
│   └── latex-template/        可选:会议模板;不放则用内置模板
├── paper.toml                 可选:LaTeX 工程的标题与作者
├── outline.zh.md              展开后的中文大纲 —— 你审、改这份
├── _work/                     中间产物(索引、英文大纲、各章工作区),一般不用看
└── output/                    交付物
    ├── paper.md / paper.zh.md     整篇初稿(英文 / 中文审阅版)
    ├── latex/                     LaTeX 工程(不编译):main.tex + sections/ + refs.bib
    ├── 待补清单.md                缺数据 / 缺引用 / 缺设计细节 / 未核验原因,按章列出
    ├── 图表清单.md                每张图的编号、图题、数据来源和绘图提示词
    ├── 数字溯源表.md              正文每个数字 → 值 → CSV 文件:行
    └── 材料检查.md
```

`python run.py --new` 建好所有文件夹并放好模板;`inbox/说明.md` 是一页速查。

## 每份材料怎么写

### idea.md —— 创新点文档(全篇最重要的输入)

论文的贡献是**创新点和原理**,实验数字只是支撑证据。方法、引言、摘要这些章节全从这份文档取材,
框架**绝不替你编创新点或机制**——这份文档没写到的设计细节,起草时会标 `[DESIGN DETAIL NEEDED]`
交回给你。写得越具体,初稿越好。模板在 `inbox/idea.md`,共 8 节:

| 节 | 写什么 | 用在哪 |
|---|---|---|
| 1. 一句话贡献 | 把整篇论文的贡献压成一句话,要具体到对象和效果 | 摘要、引言反复用到 |
| 2. 问题与动机 | 现状哪里不行、为什么重要、为什么之前没被解决 | 引言、相关工作 |
| 3. **核心洞察** | 为什么你的方法能 work。这是审稿人最想看的一段,也是最不能靠数据倒推的一段 | 方法、引言 |
| 4. **方法设计** | **可复现级别**的细节:总体结构与数据流、关键组件(输入/输出/作用)、公式与符号(每个符号给定义,全文统一沿用)、设计选择与替代方案 | 方法章直接从这里展开 |
| 5. 与最近工作的区别 | 对每个最相关的工作,说清**差在哪**(表格:相关工作 / bib key / 它做了什么 / 我们的不同) | 相关工作、引言 |
| 6. 论文声称的贡献清单 | 按重要性一条一句。这份清单是“允许声称的上限”——框架不替你加,评审也会查正文有没有声称超出它的东西 | 引言、结论 |
| 7. 已知局限 | 你自己知道的短板 | 局限、讨论 |
| 8. 预期结论 | 读者读完应该记住什么。写“论点”,不写“数字” | 结论 |

最起码要填 **第 1、3、4 节**;只有模板、没有作者内容的 idea.md 会被材料检查拦下。
**不要在 idea.md 里写实验数字**——数字只来自结果表,经占位符替换进正文。

### outline_draft.md —— 章节骨架表(你手填)

只填一张表:`# | 章标题 | type`。分几章、叫什么、什么顺序、什么 type 由你定,框架不替你决定。
type 决定这章从哪取材、数字管多严,词表在模板末尾(`abstract / intro / related / background /
method / theory / experiments / results / analysis / ablation / discussion / limitations /
conclusion`,中文别名也认)。小节和起草要点不用写:`--go` 会让规划者读 idea.md 展开成
`outline.zh.md`,你审完/改完再跑。

### results/ —— 结果表(每个 CSV 是论文里的一张表)

```
results/
├── 主结果.csv        ← 一张表一个文件,只放最终结果
├── 消融.csv
├── 效率对比.csv
└── 实验设置.md       ← 数据集、指标、对比方法、超参、硬件、种子数、各表说明
```

CSV 约定(程序按它渲染表格和数据索引):

- **第一列是方法/配置名**,其余列是指标。
- 列名结尾的 `↑` / `↓` 表示越大 / 越小越好——程序据此在表里**加粗每列最优值**。
- `X_std`(或 `X_stderr`、`X_se`)列是指标 `X` 的标准差,表里自动拼成 `均值 ± 标准差`。
- 数字**保留 CSV 原样**:`76.10` 不会变成 `76.1`。引自别人论文的数字同样放在这里(对比结果
  本来就是表的一部分);表注里写明哪些是原论文报告的、哪些是复现的。
- 表头会**原样出现在论文里**,建议用英文。
- 框架不替你求均值:论文要报均值/标准差,请自己算好放进 CSV。
- 多 seed 的 CSV 要加一列 `seed`(或 `run` / `run_id` / `trial` / `fold`);同一指标出现多个不同取值
  而没有身份列区分时,材料检查会报冲突(不猜哪个是哪个)。
- 文件名含 `.example.` 的会被忽略(模板里的示例就是这样)。

`实验设置.md` 由实验类章节**整份读取**:写了什么,正文才能写什么;没写的细节只会标 `[UNKNOWN]`。

### references/ —— 文献室

```
references/
├── refs.bib                   ← 总 bib:正文能引用的 key 只有这里有的
├── resnet/                    ← 每篇一个文件夹,文件夹名随意
│   ├── 笔记.md                  笔记(按 笔记模板.md 写)
│   └── paper.md                 原文
└── ...
```

- 笔记头部的 `doi` → `arxiv` → `title` 依次去 `refs.bib` 里找对应条目,所以文件夹名、文件名随意;
  没填的占位值(`xxxx.xxxxx`)当作空。对不上会在材料检查里报错。
- 写作模型**默认只读笔记**(经 `read_reference`),需要细节时才用 `search_reference_text(key, 关键词)`
  取原文片段(长度有上限,每次查阅都记在本章的 `fulltext-lookups.md` 里,方便你核对)。
- 笔记里 **“对我的研究的启发”** 和 **“延伸阅读”** 两节**不会给模型看**(那是你自己的想法)。
  “局限性”里的“社区讨论中的观点”是别人的观点,不会被当成这篇论文自己的主张。
- 相关工作只写“别人怎么做、效果好不好、局限在哪”这种笼统描述,不写具体数字。
- 笔记里 `[[...]]` 提到的论文,不在 `refs.bib` 里就不能引。
- 没有笔记的 bib 条目只能按题录引用,不能描述它的内容。

### code/ —— 实验代码(可选)

整个文件夹拖进来即可。系统只做**静态解析**(`ast.parse`,不导入、不执行):文件树、入口脚本、
命令行参数默认值、配置文件里的超参,生成 `code-index.md`。它只供实验设置章参考——代码里的默认值
不等于实际跑实验时用的值,所以正文引用它的句子必须标 `[FROM CODE — 需核对]`,并进待补清单。

### latex-template/ —— 会议模板(可选)

有目标会议的模板就整个放进来:`main.tex` 里正文位置写一行 `% PAPER_BODY`(摘要和各章 `\input`
会插在那里),`.cls` / `.sty` 原样复制。不放则使用内置的极简模板。**本系统不编译 PDF**。

## 防编造机制

| 机制 | 做法 |
|---|---|
| **数字不经模型之手** | 结果数字只能写成 `{{RES-xxx}}` 占位符(逐字复制数据索引里的编号),定稿时程序替换成 CSV 原文;未知编号留显式空洞 `⟨未知结果⟩`,不编值 |
| **派生数字由程序算** | 两个结果的差 / 相对提升写 `{{DIFF:RES-a,RES-b}}` / `{{REL:RES-a,RES-b}}`,程序计算,溯源表写明怎么算的 |
| **结果表由程序渲染** | 正文写 `[TABLE: 表名 \| caption: … \| note: …]`,表里所有数字来自 CSV,按 ↑/↓ 加粗最优 |
| **数字门禁** | 手打进正文的数字对回结果库(定稿前后各查一次) |
| **引用白名单** | 只认 `refs.bib` 的 key;评审提出的“缺引用”建议里的 key 不在库里就不插入;定稿里的未知 `\cite` 进核验原因 |
| **阶段指纹** | 提示词 / skill / 模型 / idea.md / 结果表变了再跑,旧产物按陈旧硬停,不静默复用 |
| **写入隔离** | 章节运行期间 Agent 只能写本章目录;inbox 和 outline 物理只读;Agent 不能导入 `os`;读不了 `inbox/references/` 的原始笔记 |
| **核验状态** | “生成完成”不等于“核验通过”:数字缺口、未知引用、未知表名、MUST FIX 没清空,都标 `未核验`,在待补清单里列出 |
| **缺口如实** | 缺数据 `[MISSING DATA]`、缺引用 `[CITATION NEEDED]`、缺设计细节 `[DESIGN DETAIL NEEDED]`、代码细节 `[FROM CODE — 需核对]`;允许带显式缺口的初稿,不允许把它报成全部通过 |

**失败即停,缺口继续**:流程失败(缺必需材料被拦下、阶段出错、备料/证据挖掘没产出)立刻停,
修好后重跑从这一章继续;“这章跑完了但有缺口”(数字找不到、引用对不上)不算失败,继续写下一章,
缺口汇总在 `待补清单.md`。

## 三个 Agent

| Agent | 角色 | 典型模型 | 职责 |
|---|---|---|---|
| **规划者** Manager | 规划 | Claude Opus / GPT-5.x | 读 idea.md 展开大纲、从文献索引为每章备料、起草前规划、统一术语 |
| **起草者** Draft | 写作 | Claude Opus | 挖证据、写正文、改稿 |
| **评审者** Review | 审稿 | GPT-5.x / Claude Opus | 评审、验改、定稿、跨章交接 |

三者**平级**,只通过读写文件协作。推进、门禁、断点续跑、重试全是确定性的 Python 代码。
三个 Agent 的 provider / model / key 各自独立(OpenAI 走 `OpenAIModel`,Claude 走原生
`/v1/messages`,可任意混搭),见 `.env.example`。

## 分步命令

```bash
python run.py --new 项目名 [--parent 目录]            # 建项目
python run.py --project <项目> --check               # 只做材料检查
python run.py --project <项目> --index               # 只建三份索引(文献 / 数据 / 代码)
python run.py --project <项目> --expand              # 只展开大纲
python run.py --project <项目> --init [--force]      # 只生成各章工作区
python run.py --project <项目> --all                 # 只逐章生成
python run.py --project <项目> 03-results            # 只跑一章
python run.py --project <项目> --assemble            # 重新核验各章终稿并组装(不调模型)
python run.py --project <项目> --list                # 各章状态
python run.py --project <项目> --go --keep-outline   # idea / 骨架改过后,确认继续沿用旧大纲
```
