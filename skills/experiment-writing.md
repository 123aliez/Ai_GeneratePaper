# Experiment-Paper Writing — 实验论文写作专属规范

> 起草实验论文时按需读取。这是本框架的核心规范,统领其他 skill。

## 两个源,先认清你在写哪类章节

**论文的贡献是创新点和原理,实验数据只是支撑证据。** 起草前先看提示词里的
`CHAPTER TYPE` 子句,它告诉你这段属于哪一类:

| family | 主源 | 另一个源的角色 |
|---|---|---|
| `idea` | **`idea.md`**(作者写的全局文档,读全文) | 数字只作辅助,最多引一个 headline 数 |
| `data` | **数据索引 `data-index.md`**(每张结果表一个 `{{RES-xxx}}=值` 网格)+ 实验设置.md | idea.md 只用来决定 narrative,不重述方法设计 |
| `mixed` | 两者并重 | 论断来自 idea.md,支撑来自数据索引 |

**不许跨类型代偿**:方法章不许用实验结果代替机制解释("我们的方法涨了 3.4 点"
不是"为什么这样设计能work"的答案);结果章不许用方法阐述填篇幅。

## 内容取舍与证据边界
- 先确定本章要回答的问题及读者应带走的发现，再选必要的机制、比较和解释。材料完整可读，不代表正文必须全部覆盖。
- 正文保留核心机制、必要公式与定义、关键结果，以及影响理解、复现核心方法或判断比较公平性的条件。指标分母、数据划分、重要反例和不确定性不能为简洁而删。
- 常规配置清单、次要推导和完整运行记录不逐项写入正文。可用的补充材料承担细节；没有补充材料时，在计划或 todo 中记录建议，不虚构附录及其引用。
- 文件路径、运行编号、证据核验、缺口处理及修订过程留在内部材料中。正文使用科研对象的名称，数字溯源由占位符和系统记录承担。
- 预算用于分配篇幅，不是最低字数。内容已经完整时允许少写，不用更多设置说明或重复结论填满。

## 创新点纪律(idea 类章节最高优先)
- **创新点、机制、方法设计只能来自 `idea.md`**,那是作者自己的表述
- 不许**弱化**也不许**放大**作者的论断;贡献清单以外的贡献一律不许声称
- idea.md 没写到的设计细节标 `[DESIGN DETAIL NEEDED]`,**绝不"合理地"补一个**
- 整份创新点文档缺失时标 `[IDEA NEEDED]`——框架会拦住,不该走到起草这步
- 解释机制要回答"为什么work",不是"效果多好"

## 数字纪律(data 类章节最高优先)
- **每个结果数字必须来自结果表**:只写 `{{RES-xxx}}` 占位符(差值/相对提升写 `{{DIFF:..}}`/`{{REL:..}}`),整张表写 `[TABLE: …]`,不手打数字
- 内部计划与证据包记录数字来源；正文用方法名、数据集名、指标和必要协议说明比较，占位符提供溯源，不复述 CSV 键、运行编号或核验过程。
- 需要写的数字缺失时标 `[MISSING DATA]`,绝不猜、绝不 extrapolate;没做的实验不要专门写一句去标
- 讨论如需引用数字，必须与结果一致；通常直接解释已建立的发现，无需每条论断重报数值。
- idea 类章节引 headline 数时同样受这条约束:不在数据索引里的数字一律不许写

## 章节内容边界
| 章节 | type | 只写什么 |
|---|---|---|
| Abstract | `abstract` | 问题+方法+最强量化结果(数字只能是 `{{RES-xxx}}` 占位符) |
| Introduction | `intro` | 动机+贡献清单(**照 idea.md 的清单,不加不减**),每个贡献要有后续支撑 |
| Related Work | `related` | 用文献索引与笔记 + idea.md 的 delta 表;只写别人怎么做、效果好不好、局限在哪,不写具体数字 |
| Background | `background` | 预备知识和记号;不掺入本文贡献 |
| Method | `method` | **从 idea.md 展开机制与设计选择**;只写真正实现的;遵守 Notation Table |
| Theory | `theory` | 从 idea.md 的公式出发;假设要写全 |
| Experimental Setup | `experiments` | 只写 实验设置.md 里有的;代码细节标 `[FROM CODE — 需核对]`;都没有标 [UNKNOWN] |
| Results | `results` | 只写结果表里的;结果表用 `[TABLE: …]`;禁幻觉;不重述方法 |
| Ablation | `ablation` | 逐个组件对照;只写做了的消融,没做的不提 |
| Discussion | `discussion` | 综合解释已报告结果的意义、适用条件和权衡;区分 supported vs suggests;不逐项重报数字 |
| Limitations | `limitations` | 以 idea.md 的「已知局限」为底,加数据暴露的短板 |
| Conclusion | `conclusion` | 提炼已 demonstrated 的核心贡献与意义;无新数字;仅当大纲没有另设局限位置时承接重要局限 |

## 与占位符/公式结合
- 结果里的图表:按 `figure-table-placeholder.md` 写占位符 + 说明,不生成图
- 公式:按 `math-formula.md` 用 LaTeX 语法,符号遵守 Notation Table
- 方法章节的符号必须和 Notation Table 一致,不重定义
- idea.md 里作者已定义的符号**直接沿用**,不另起一套记号

## 防幻觉铁律
- 不臆想**创新点或机制**(idea.md 里没有的 → `[DESIGN DETAIL NEEDED]`)
- 不臆想硬件/超参/数据集大小(实验设置.md 里没有的 → `[UNKNOWN]`)
- 不臆想未跑的实验/消融；缺失信息若影响必需论断则标 gap，否则记内部待办，不生成缺项清单式正文
- 不臆想显著性(没有检验/区间数据 → 只描述趋势,不 assert significance)
- 证据挖掘答不出时在**内部证据包**写 "I cannot answer from the provided evidence"；正文不出现这句流程话。必需内容缺失时保留对应缺口标记并记 todo，不硬编。

## 写完后自检
1. 这段的 `CHAPTER TYPE` 是什么?主源用对了吗?
2. idea 类:机制是**解释**了还是只**断言**了?设计选择给理由了吗?
3. idea 类:声称的贡献都在 idea.md 的贡献清单里吗?
4. data 类:每个数字都是占位符/渲染表,没有手打?
5. Discussion 是否在解释发现，而非重述 Results；若重引数字是否一致?
6. 每张图占位符都有数据来源 + 支撑论断?
7. 每个符号首次使用都定义了,且与 idea.md 一致?
8. 每段是否有独立的论证作用；内部核验和常规清单是否挤占了核心解释?
