# 顶会 / 顶刊写法精要

> 起草每一章时都按本规范写。提炼自 Peyton Jones《How to write a great research paper》、
> ICML / NeurIPS 的写作与审稿要点、Nature 摘要写法、ML 论文写作指南。目标:读者最短路径抓住
> 那一个想法,并理解证据支持到哪里。按论点选择内容，综合局限放在审定大纲指定的位置。

## 整篇故事线(每章服务其中一环)
问题是什么 → 为什么值得做 → 我们的想法(一句话)→ 它为什么有效 → 实验证明它有效 → 和已有做法的关系。
**一篇论文只有一个"叮"(one ping)**:一个清晰、锋利的核心想法,贡献都围绕它。
读者的最短路径:不复述研究过程和试错,直接走向想法。

## 摘要(150–250 词,一段)
按功能写,一句一职能,顺序固定:
1. 背景:领域里这件事为什么重要(1 句,外行也懂)
2. 缺口:已有做法缺什么 / 具体问题是什么(1–2 句)
3. 方法:`We introduce/propose X, which ...`(照 idea.md 的一句话贡献,不自己重新概括)
4. 结果:按计算机视觉 / 机器学习顶会(CVPR、ICCV、NeurIPS、ICML)的惯例,用**一句话**给出
   最亮的结果,至多两个数字(`{{RES-xxx}}` / `{{DIFF:..}}` 占位符),**概括全部对比设置**
   (如"在三种深度上相对基线降低 a–b 个点,计算量几乎不变"),说明相对什么基线、在哪个基准上;
   不挑单个模型的原始数值罗列。(Nature 类期刊摘要不放数字,本项目面向 CV/多模态方向,按会议惯例。)
5. 意义:这对领域意味着什么(1 句)
开头不能是"任何论文都能用的"泛泛背景;不放引用、缩写先展开、不放小标题。

## 引言(约一页)
1. **用一个具体例子或具体现象引出问题**,不用"X 非常重要[1,2,3]"式的大话;小山丘,不是大山。
2. 说清现有做法为什么在这个问题上不够(一两句,具体)。
3. 一句话讲出本文想法。
4. **贡献清单**(2–4 条项目符号):每条**具体、可被证伪**,并带前向引用到支撑它的章节。
   - 弱:"我们提出了一个新框架,效果很好。"
   - 强:"我们提出 X,在 Y 上把 Z 从 a 降到 b(Section 5)。"
   - 贡献只能来自 idea.md 的清单,不加不减。
5. **不写"本文余下结构如下……"**;用叙事里的前向引用串起全文。
引言里每一条论断,都要能在正文找到证据。

## 方法
- **先直觉,后形式**:先用一个具体例子或一句直白的话讲这个模块在做什么,再给公式;
  读者有了直觉才跟得住细节。
- 每个关键设计都回答"为什么这样设计",而不只是"是什么";
- 只写最终采用的设计，符号一致。讲清核心机制及必要的维度、超参、位置与假设；常规实现清单、次要推导不与创新机制平均分配篇幅。不能把理解或复现核心方法必需的信息推给不存在的附录。

## 实验
- **每个实验开头先写它要验证的论断**("为了检验 X 是否 Y,我们……"),不先摆数字。
- 按"设置 → 结果 → 解读"分开写;设置只写读者判断结论可信所必需的(数据、协议、训练配置)。
- 结果小节以发现开头("X 在全部三个深度上都降低了 top-1 错误率"),再给数字、再给一句解读;
  一个小节对应一个论断,配一张表或一张图。
- 解读要回答"为什么会这样 / 说明了什么",而不是重述表格。
- 对比是同口径、同设置的对比;说清比较的对象与指标方向。
- 选择能回答科学问题的关键比较，保留会改变结论的失败情况、反例和不确定性。表中已有数字不逐格翻译为句子，协议与指标定义在所属位置说明一次。

## 相关工作
- 按**方法路线 / 主题**分组,不逐篇罗列;每组末尾一句话说明本文与它的关系与差异。
- 慷慨地肯定前人("X 的开创性工作……,我们在此基础上……"),不贬低对手;信用不是零和。
- 只写别人怎么做、做得怎样、边界在哪;不写他们的具体数字。

## 讨论与结论
- 讨论把结果放到更大的背景里解读,**不重复结果章**;说明它意味着什么、能用在哪。
- 结论:回到引言的贡献清单,逐条说明已经做到了什么;给出一个向前看的方向。
- 综合局限按审定大纲归入指定章节，集中解释重要边界；使具体论断成立的假设与条件在该论断处保留，不以简洁为由隐藏。

## 整章编辑
- 用一句话概括本章发现，再检查每段是否推进问题、机制、证据或解释。没有独立作用的段落删并。
- 内部证据包可以逐项核验，论文正文必须有主次。删掉运行记录叙述、核验过程、重复定义和表格复述，保留必要的科学信息。
- 首轮修订先做结构编辑，再做语言润色；不要把“修复评审问题”等同于在每段末尾补一句解释。
- 按预算展开推理，保留不利证据。多阶段方法可用紧凑步骤说明训练和推理，有材料时交代参数与计算开销。解读结果时比较收益与退化出现的条件，区分实测机制和待验证解释。

## 段落与句子
- **段首直接进入内容**:不写"如引言所述""承接上一章"之类指向别的章节的元叙述开头;
  需要回指时用一个短语(如"under the protocol in Section 5"),不占整句。
- 每段只讲一件事,主题句在第一句;段与段靠论证逻辑衔接。
- 主动语态("We analyze"),被动语态会让文章发闷;句子 15–25 词,长短错落。
- 具体胜过笼统:写出模块名、数据集名、数值,不写 "good performance"。
- 同一概念全篇一个词;缩写首次出现展开,此后只用缩写。
- 每个论断旁边就是它的证据(数字、表、公式、引用);没有证据的话不说。

* **引言**：默认不拆 `1.1/1.2` 二级标题，用自然段流畅推进；贡献清单前不加复述性过渡段；每条贡献严格控制在 **1–2 句（≤ 45 词）**，直接写“做了什么 + 支撑章节”，去掉防御性免责声明和细节展开。
* **相关工作**：按 2–3 条技术路线横向归纳，禁止单篇写成小作文（A 类文献每篇 ≤ 1–2 句）；不要在每个小节末尾重复介绍本文方法，每组末尾用一句话点明差异即可。
* **方法**：每个核心前提与设计理由在首次出现时说清一次即可，不跨小节反复重复，不单独开设复述性的 `Design Rationale` 小节。
* **实验**：不把完整实验过程与搜索网格搬进正文，不单独设节讲指标；正文表格只保留重要指标列，不出现标准差描述；表注 ≤ 2 行，所有变体说明与结果解读直接放入正文；正文不逐条罗列流水账式 $p$-value，改用表格星号标记与正文提炼核心幅度。
